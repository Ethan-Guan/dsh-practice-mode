# 刷题模式（Practice Mode）

一个 DeepSeek Harness Web GUI 插件：把 **课程文档 → 题目解析 → 刷题练习 → 学情看板 → 复习方案** 串成一条学习闭环，并在右侧提供与刷题内容联动的 AI 答疑对话。

## 安装

在目标电脑的 DeepSeek Harness 中打开 **插件 → 添加插件**，填入下面的安装源（需要该电脑能访问 GitHub）：

```
github:Ethan-Guan/dsh-practice-mode
```

也可以先 `git clone` 本仓库，再在「添加插件」里选择本地目录。安装后在插件列表确认「刷题模式」已启用；新增插件通常要重启一次 DSH 才会加载新的模块。

## 功能

### 入口与布局
- 左侧插件栏新增「**刷题模式**」图标；点击后主区域进入刷题工作台。
- 工作台由中间刷题区（核心）与右侧对话卡片组成；课程管理与整体数据统一放在「所有课程看板」页（打开插件后的默认页），点击课程卡片进入课程主页。右侧对话会随刷题内容自动带入上下文（当前题目 / 选中文字 / 课程文档）。

### 课程与资料
- 新建 / 编辑课程，每个课程独立保存文档、套题、作答记录与对话。
- 上传课程文档：PDF、DOCX、PPTX、TXT、MD、CSV、JSON、HTML；支持多选文件、**整个文件夹（保留目录结构）**，也支持把文件/文件夹**直接拖入**「课程文档」或「题目集」区域上传。
- 课程文档列表按上传目录分组展示，并支持**折叠**（默认收起，按课程记忆展开状态）；右侧答疑与学情分析会携带「课程文档目录树」，AI 可依据目录/相对路径定位资料，引用时显示相对路径。
- 上传后自动抽取文本用于「基于课程文档」的答疑与复习建议（PDF 文本层尽力抽取；不可抽取时仍保留原件）。
- 每套题在课程下新建；刷完一套可继续上传下一套。

### 题目解析
- 上传题目文件：PDF、DOCX、PPT、PPTX、图片（PNG/JPG/WebP）、TXT、MD，可一次多份（同一套题）。
- 题目/答案文件**直接交给 Agent**（不预先渲染成页面图片）：每个文件一次 Agent turn，工作目录就是 `courses/<courseId>/sets/<setId>/source`；提示词里给出**完整 JSON 格式**（title/groups/questions 字段），Agent 读取原件后按格式提交，Host 再规范化匹配。
- 结果读取以 **Session 日志里最后一条 assistant 消息 / 提交工具参数** 为准：流式监听漏掉最后一条、或超时前已经提交，都能拿到结果；超时/中断时优先保留已提交的题目。
- 表格由 Agent 解析为 Markdown 表格直接显示；图形/类图由 Agent 给出内联 SVG 或图片路径；共用材料不再用卡片包裹，直接显示。之前解析过的旧套题需点「重新解析」才会获得新流程效果。
- **答案文件**：试卷与答案分成两个文件时，可在套题卡片上「补传答案」（PDF/Office/图片/文本），解析时同样直接给 Agent 原件，按题号把答案匹配进题目；**答案里的图**（ER 图、时间线、截图）会解析成 `answerFigures` 并在答案区显示。也可对已有套题「重新解析」应用答案更新或 AI 策略。
- **AI 答案解析策略**（每套题可设置，重新解析后生效）：
  - 自动补充缺失答案（默认）：原卷/答案文件有的答案优先，只对缺答案题生成 AI 参考；
  - 不生成 AI 答案：完全只使用原卷/答案文件；
  - 全部 AI 重新生成：忽略原卷答案，全部用 AI 生成，并在解析区保留原卷答案供核对（适用于原卷答案可能有误的试卷）。
- Host 不再把 PDF / Office 转成页面图，也不抽取课程文档文本：课程文档目录只作为该课程 Agent 的工作目录。
- **参考答案设计（两阶段）**：
  - 解析阶段只转录原卷：原卷明确给答案/解析 → 直接采用（标记「原卷答案」）；原卷没有答案 → 不臆造，留空等待第二阶段；
  - 解析完成后自动进入「AI 参考答案」阶段：Agent 的工作目录就是这门课的课程文档目录（`courses/<courseId>/docs`），需要依据课程资料时自行 `read` / `grep`；生成答案与解析（答案图用 `answerFigures`）；课程文档无直接依据时退化为通用知识参考（标记「AI 生成参考答案」，提示核对）；生成失败则显示「暂无参考答案」，仍可一键提问；
  - 作答判分：有 answers 的客观题自动判分；无答案或主观题在查看答案后自评。
- 解析为结构化题目，适配：
  - 题型：单选、多选、判断、填空、简答；
  - **跨多题的共用题干 / 阅读材料**（groups）；
  - 图形题：Agent 可给出裁剪图片路径或内联 SVG；也支持在题目上点「重新绘制」让 Agent 再次生成；
  - 原卷有答案 / 解析时优先使用，没有时由 AI 生成答案与解析。
- 解析在后台任务中进行，界面显示进度，失败可重试。

### 刷题
- 两种看答案模式，可在开始一套题时选择：
  - **答一题看一题**：提交后立即显示答案与解析；
  - **全部做完再看**：交卷后统一显示答案与解析。
- 逐题作答、上一题/下一题、题号导航（已答对/已答错/未答/当前题）、自动判分（填空/简答支持自评）。
- 题目/选项/解析支持富文本展示：保留空格、缩进与真实换行，支持代码块（``` 围栏或缩进代码）、行内代码、Markdown 表格（自适应、可横向滚动）等；顶部条可调题目字号（80%–150%，自动记忆）。
- 答案解析区：
  - 显示正确答案、解析、考点；
  - 「**一键提问**」：直接让右侧对话区详细讲解该题（解题思路、考点、易错点，结合课程文档）。
- 刷完一套显示本套统计（题数、正确率、用时、题型正确率），可再练、继续上传下一套或生成复习建议。
- 题目/共用材料中的图片**点击即可固定到左侧图片区**：支持缩放（25%–400%）与拖动分隔条调整占比（18%–60%，自动记忆），方便对照题图作答。
- **提交即 AI 判题**：标准答案已经由原卷/答案文件准备好，AI 只做**快速比对**（不重新解题、不查文档）：先显示标准答案（含答案图片），再给出判定、错在哪与简短理由；解析不超过 3 句。即时模式提交后等待批改再显示解析，全部做完模式后台批改、交卷时等待完成；AI 失败自动回退本地判分。
- 答案可**重新提交**：答案 reveal 后点「重新作答」即可修改并再次提交，会重新判卷并覆盖该题记录；「全部做完再看」模式下再次提交也会重新判题。

### 右侧对话
- **只在答题界面出现**（课程主页/看板不显示），每个课程使用一个**真实 DSH Agent Session** 进行多轮流式问答；工作目录是这门课的课程文档目录，Agent 需要时可自行 read/grep。
- 注入的上下文只有**当前题目 + 我的回答**（以及选中文字）；不再注入课程文档内容或文档清单。
- 对话区宽度可拖拽调节（280–640px，双击手柄恢复默认），也可一键收起为窄竖条，宽度与收起状态会记住。
- 在刷题区**框选任意文字** → 浮动「提问」按钮 → 自动附加到右侧对话栏，可继续输入问题后发送。
- 对话记录按课程持久化，可新建 / 清空对话。

### 数据看板与复习
- **课程看板**：刷题数、正确率、已完成套数、复习天数；题型正确率、最近 7 天趋势、近 16 周活跃度热力图；易错题列表（可跳转到题目）；AI 学情分析（结合课程文档生成易错点、复习重点与 7 天复习计划）。
- **所有课程看板**：总刷题量、总正确率、活跃天数；近 16 周活跃度热力图；课程对比；最近活动；全局 AI 学情分析。

## AI 调用方式

插件的所有 AI 能力都直接使用 **DSH Agent / Session**（不再走 `ctx.llm` 直连，也不再导出可编辑提示词文件）：

- 解析、答案整理、AI 答案、判题使用单轮 Agent；提示词只包含「任务说明 + 原始文件/题目数据 + **明确的输出格式**」，结构化结果由 `submit_*` 工具直接回传；
- 题目/答案文件直接给 Agent 原件，不预渲染页面图；Agent 自己决定读文本层还是看图；
- 答疑使用每门课一个持久 Agent Session，cwd 为该课程的课程文档目录；上下文只有当前题目与我的回答；
- 判卷使用已准备好的标准答案，不读文档、不重新解题，90 秒超时；
- 学情分析与图形重绘由 Agent 直接返回 Markdown / SVG；
- 工具范围按任务收窄：判卷只允许 `submit_grade`；解析/答案整理允许读文件与必要的 bash/write，其他工具被 guard 拒绝。

`~/.dsh/practice/prompts/` 是旧版本导出的提示词文件，新版本不再读取，可以删除。

## 环境要求

- DeepSeek Harness Desktop（内置 Node 运行时与 LibreOffice Kit；插件会通过 `process.resourcesPath` 自动发现）。
- 已配置可用的模型（默认跟随当前配置的默认模型）。题目/答案文件直接交给 Agent；扫描件/图片题需要模型支持图片输入，文本层完整的 PDF / Office / 文本题目不需要。
- 数据默认存放在 `~/.dsh/practice/`（`$DSH_HOME/practice`）：
  - `store.json`：课程、套题摘要、作答记录、分析、对话索引；
  - `courses/<courseId>/docs/`：课程文档原件（同时是该课程 Agent 的工作目录，不抽取文本）；
  - `courses/<courseId>/sets/<setId>/`：题目/答案原件、`source/` 工作目录、`set.json`；
  - `courses/<courseId>/assets/`：题目图片与 SVG；
  - `courses/<courseId>/chat/`：对话记录。

## 使用步骤

1. 点击左侧插件栏「刷题模式」。
2. 在「所有课程看板」页点击「新建课程」（或选择已有课程卡片进入课程主页）。
3. 在课程主页上传课程文档（可整个文件夹）。
4. 上传一套题目文件；等待解析完成。
5. 选择看答案模式开始刷题；随时可框选文字或点「一键提问」向右侧提问。
6. 交卷后查看本套统计；回到课程主页查看课程看板，生成学情分析与复习方案。
7. 继续上传下一套题，或到「所有课程看板」对比学习情况。

## 故障排查

- **入口没有出现**：在 Settings → Plugins 中确认「刷题模式」已启用；启用后刷新页面。
- **题目解析失败**：确认 `~/.dsh/practice/.status.json` 中 `agent: true`；原卷是扫描件时 Agent 需要能读图。可先上传 TXT / MD 题目验证流程。
- **解析很慢**：每个文件一次 Agent turn，PDF 文本层提取可能较慢；失败可重试。
- **看不到课程文档内容被引用**：PDF 需要文本层；扫描件 PDF 暂无 OCR，仅作为背景资料保留。

## 开发

```sh
# 构建 client 半（Lead/维护者运行）
"<bundled-node>" tools/build-client.mjs
"<bundled-node>" tools/check-package.mjs
# Host 单元测试
"<bundled-node>" --test test/*.test.mjs
```

安装（由 Harness 的 Plugin Manager 完成）：`install_bundle` + 包目录绝对路径；Host 行写入 profile patch，Client 半由 `dsh.client` 声明由 Web GUI 加载。

包结构：

```
index.js                 Host 入口（服务接线）
lib/host/store.js        持久化（store.json 原子写）
lib/host/jobs.js         后台任务
lib/host/api.js          HTTP API（/api/practice/*，含 SSE 对话）
lib/host/llm.js          模型状态/图片能力探测（AI 调用统一走 Agent）
lib/host/prompts.js      极短 Agent 提示、submit_* 工具 schema 与结果规范化
lib/host/agent-runtime.js  Agent 运行时（Session 日志取最终正文、提交工具、超时保留）
lib/host/tasks.js        解析 / 分析 / 重绘 / 判题 / 对话编排
lib/host/render.js       LibreOffice Kit 页面渲染
lib/host/extract/        纯 Node 文档文本抽取
src/client/*.js          Client 半片段（构建为 client.js）
```

## 已验证范围与已知限制

**安装与注册（已通过）**
- 通过 Plugin Manager `install_bundle` 安装为 profile bundle；Host 行 `practice-mode` 处于 active。
- 左侧插件栏 `sidebar.panellist` 已注册「刷题模式」入口（id=`practice-mode`，图标可见性由宿主渲染）；主区 `main` 槽位已注册 key=`practice-mode`。
- Host 诊断文件 `~/.dsh/practice/.status.json`：模型解析为 `deepseek-official / deepseek-flash`，`images: true`（多模态可用）、`render: true`（LibreOffice Kit 可用）。
- 全部 102 项单元/集成测试通过，包含：真实 LibreOffice Kit 的 DOCX→PDF→PNG 页面渲染链路、文档抽取（DOCX/PPTX/PDF 文本层）、题目 JSON 规范化（跨题材料/SVG 清洗/批处理合并）、Agent 运行时（提交工具、Session 最终正文、超时保留）、store 原子写与路径越界防护、18 条 HTTP 路由（假 ctx 下）、SSE 对话帧顺序。

**未在当前环境完成的验证**
- 本会话没有浏览器控制能力，因此**未进行真实点击级别的 UI 验证**（三栏布局、按钮交互、拖拽上传、流式渲染的视觉效果需要用户实际打开页面确认）；插件注册、模块装载、Host 服务可用性均已由槽位检查与诊断文件确认。
- 未做真实模型的完整「上传 PDF → 解析 → 作答 → 对话」端到端调用（会消耗真实 token 且需要用户在界面中操作）；Agent 提交工具、最终正文读取与输出规范化已有单测覆盖。

**已知限制**
- 数学公式按纯文本（LaTeX 源码）显示，未集成 KaTeX/MathJax。
- 扫描件 PDF 无 OCR：题目解析通过页面渲染图 + 多模态模型完成，通常可用；课程文档若为扫描件则无法抽取文本用于问答（仍保留原件）。
- 同一题反复练习只保留最新一条作答记录（按 record.id upsert），不会保留多次历史尝试。
- 「重新解析」会保留旧渲染页图文件（不被引用，不占 UI）。
- 如果部署未挂载 attachments 服务或模型不支持图片，图片/PDF/Office 题目解析会返回中文错误；TXT/MD 题目不受影响。
